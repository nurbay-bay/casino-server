# Проверка серверной части для работы с платежами

## ✅ Реализованные функции

### 1. Автоматическая отмена истекших платежей

**Реализация:**
- Функция `cleanupExpiredPayments` в `src/db/cleanup.ts`
- Запускается каждые 5 минут через `setInterval` в `src/app.ts`
- Автоматически находит все pending платежи с истекшим `expiresAt`
- Отменяет PaymentIntent в Stripe
- Устанавливает статус `canceled` в базе данных

**Проверка:**
```bash
# Создайте платеж и подождите 15 минут
# Проверьте логи сервера - должно появиться сообщение:
# [CLEANUP] Отменено X истёкших платежей
```

---

### 2. Endpoint отмены платежа

**Endpoint:** `POST /api/payments/cancel/:token`

**Реализация:**
- Функция `cancelPayment` в `src/controllers/payment/createPayment.ts`
- Принимает токен платежа
- Находит pending платеж
- Отменяет PaymentIntent в Stripe
- Устанавливает статус `canceled`

**Проверка:**
```bash
# Создайте платеж
POST /api/payments/create
# Получите paymentToken из ответа
# Отмените платеж
POST /api/payments/cancel/{paymentToken}
# Проверьте, что статус изменился на canceled
GET /api/payments/user/{userId}
```

**Ожидаемый ответ:**
```json
{
  "message": "Платёж отменён"
}
```

---

### 3. Обновление истории платежей

**Endpoint:** `GET /api/payments/user/:userId`

**Реализация:**
- Функция `getUserPayments` в `src/controllers/payment/paymentController.ts`
- **ВАЖНО:** Перед возвратом истории автоматически проверяет и отменяет истекшие платежи
- Возвращает актуальные статусы всех платежей, включая `canceled`

**Проверка:**
```bash
# Создайте платеж
POST /api/payments/create
# Подождите 15 минут (или измените expiresAt в БД для теста)
# Запросите историю
GET /api/payments/user/{userId}
# Проверьте, что истекший платеж имеет статус canceled
```

**Ожидаемый ответ:**
```json
{
  "payments": [
    {
      "_id": "...",
      "status": "canceled",
      "amount": 5000,
      "expiresAt": "2024-01-15T10:30:00.000Z",
      ...
    }
  ]
}
```

---

### 4. Webhook для Stripe

**Endpoint:** `POST /api/payments/webhook`

**Реализация:**
- Функция `handleWebhook` в `src/controllers/payment/webhookHandler.ts`
- Обрабатывает события Stripe:
  - `payment_intent.succeeded` → статус `success`, пополнение баланса
  - `payment_intent.payment_failed` → статус `failed`
  - `payment_intent.canceled` → статус `canceled` (исправлено!)

**Проверка:**
1. Настройте webhook в Stripe Dashboard
2. URL: `https://your-domain.com/api/payments/webhook`
3. События: `payment_intent.succeeded`, `payment_intent.payment_failed`, `payment_intent.canceled`
4. Проверьте, что статусы обновляются корректно

---

### 5. Получение статуса платежа по ID

**Endpoint:** `GET /api/payments/status/:paymentId`

**Реализация:**
- Функция `getPaymentStatus` в `src/controllers/payment/paymentController.ts`
- **ВАЖНО:** Автоматически проверяет и отменяет истекшие pending платежи перед возвратом
- Возвращает актуальный статус платежа

**Проверка:**
```bash
# Создайте платеж и получите paymentId
POST /api/payments/create
# Запросите статус
GET /api/payments/status/{paymentId}
# Проверьте актуальный статус
```

**Ожидаемый ответ:**
```json
{
  "id": "507f1f77bcf86cd799439011",
  "status": "canceled",
  "amount": 5000
}
```

---

### 6. Получение платежа по токену

**Endpoint:** `GET /api/payments/token/:token`

**Улучшения:**
- Теперь ищет платеж по токену без ограничения по статусу
- Если платеж уже завершен (success/failed/canceled), возвращает его статус
- Если pending платеж истек, автоматически отменяет его

**Проверка:**
```bash
# Создайте платеж
POST /api/payments/create
# Получите paymentToken
# Запросите данные платежа
GET /api/payments/token/{paymentToken}
# Проверьте, что возвращается актуальный статус
```

## 🔍 Рекомендации для тестирования

### Тест 1: Автоматическая отмена через 15 минут

1. Создайте платеж через API
2. Проверьте, что `expiresAt` установлен на 15 минут вперед
3. Подождите 15 минут (или измените `expiresAt` в БД для быстрого теста)
4. Проверьте логи сервера - должно появиться сообщение об отмене
5. Запросите историю платежей - статус должен быть `canceled`

### Тест 2: Ручная отмена платежа

1. Создайте платеж через API
2. Получите `paymentToken` из ответа
3. Отмените платеж через `POST /api/payments/cancel/{paymentToken}`
4. Проверьте историю - статус должен быть `canceled`
5. Попробуйте отменить еще раз - должна вернуться ошибка 404

### Тест 3: Обновление истории с истекшими платежами

1. Создайте несколько платежей
2. Измените `expiresAt` одного из них в БД на прошедшее время
3. Запросите историю платежей
4. Проверьте, что истекший платеж автоматически получил статус `canceled`

### Тест 4: Webhook от Stripe

1. Настройте webhook в Stripe Dashboard
2. Создайте тестовый платеж
3. Проверьте, что webhook получает события
4. Проверьте, что статусы обновляются корректно:
   - Успешный платеж → `success` + баланс пополнен
   - Неудачный платеж → `failed`
   - Отмененный платеж → `canceled`

### Тест 5: Polling статуса (как на клиенте)

1. Создайте платеж
2. Каждые 3 секунды запрашивайте `GET /api/payments/status/{paymentId}`
3. Проверьте, что статус обновляется корректно:
   - При успешной оплате → `success`
   - При истечении времени → `canceled`
   - При ручной отмене → `canceled`

## 📊 Статусы платежей

| Статус | Описание | Когда устанавливается |
|--------|-----------|----------------------|
| `pending` | Ожидает оплаты | При создании платежа |
| `success` | Успешно оплачен | Webhook от Stripe (`payment_intent.succeeded`) |
| `failed` | Ошибка оплаты | Webhook от Stripe (`payment_intent.payment_failed`) |
| `canceled` | Отменен | Ручная отмена, истечение времени, webhook (`payment_intent.canceled`) |

---

## ⚠️ Важные моменты

1. **Автоматическая отмена работает в нескольких местах:**
   - Периодическая очистка (каждые 5 минут)
   - При запросе истории платежей
   - При запросе статуса платежа
   - При запросе платежа по токену

2. **PaymentIntent в Stripe:**
   - Автоматически отменяется при истечении времени
   - Отменяется при ручной отмене платежа
   - Ошибки отмены игнорируются, если PaymentIntent уже завершен

3. **Баланс пользователя:**
   - Пополняется только при успешной оплате через webhook
   - Не пополняется при отмене или истечении времени

4. **Безопасность:**
   - Endpoint отмены публичный (по токену), но токен криптографически стойкий
   - История платежей доступна только владельцу
   - Статус платежа проверяет принадлежность пользователю

## 🐛 Возможные проблемы и решения

### Проблема: Платежи не отменяются автоматически

**Решение:**
- Проверьте, что `cleanupExpiredPayments` запускается (логи сервера)
- Проверьте, что `expiresAt` установлен корректно при создании платежа
- Убедитесь, что платежи имеют статус `pending`

### Проблема: История не обновляется

**Решение:**
- Убедитесь, что клиент запрашивает историю регулярно
- Проверьте, что функция `checkAndCancelExpiredPayments` вызывается
- Проверьте логи сервера на наличие ошибок

### Проблема: Webhook не работает

**Решение:**
- Проверьте настройки webhook в Stripe Dashboard
- Убедитесь, что URL доступен из интернета
- Проверьте, что `STRIPE_WEBHOOK_SECRET` установлен правильно
- Проверьте логи сервера на ошибки верификации подписи
